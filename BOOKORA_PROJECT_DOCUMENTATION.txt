PART 1: PROJECT IDENTIFICATION & OVERVIEW
================================================================================

PROJECT NAME:
   Bookora - A Community Book Sharing & Exchange Platform

PROBLEM SOLVED:
   Bookora addresses the challenge of book accessibility and promoting a 
   reading community. Many people have books they no longer need, while others
   struggle to afford or access books. The app bridges this gap by allowing 
   users to:
   - Share books they want to give away or exchange
   - Discover nearby book listings
   - Connect with other readers in their community
   - Build a sustainable book-sharing ecosystem

TARGET USERS:
   - Book enthusiasts and avid readers
   - People interested in book exchanges and donations
   - Community members wanting to reduce waste
   - Anyone seeking to build connections through shared reading interests

WHY IS THIS IMPORTANT:
   - Makes reading more accessible and affordable
   - Builds community connections around shared interests
   - Encourages cultural exchange through literature

PART 2: KEY OBJECTIVES & SCOPE
================================================================================

MAIN OBJECTIVES:

5.3 DATABASE RELATIONSHIPS
================================================================================

RELATIONSHIP: books ←→ categories (Many-to-One)

DESCRIPTION:
   - Multiple books can belong to ONE category
   - Each book has ONE category (foreign key relationship)
   - Category is identified by the "category" column in books table

RELATIONSHIP DIAGRAM:
   
   ┌─────────────────┐         ┌──────────────────┐
   │   categories    │         │      books       │
   ├─────────────────┤         ├──────────────────┤
   │ id (PK)         │◄────────│ category (FK)    │
   │ title           │ 1 : Many│ ... other cols   │
   └─────────────────┘         └──────────────────┘

ADDITIONAL RELATIONSHIPS (Implied, not enforced in Room):
   - books.ownerId → users table (One-to-Many: User has many books)
   - favorites.bookId → books.id (Many-to-Many: Users favorite books)
   - messages.conversationId → conversations table


5.4 DATA ACCESS OBJECTS (DAOs)
================================================================================

DAO 1: BookDao (Interface for book operations)
Location: data/local/dao/BookDao.kt

OPERATIONS:

   @Query("SELECT * FROM books ORDER BY postedTimestamp DESC")
   suspend fun getAllBooks(): List<BookEntity>
   PURPOSE: Fetch all books, newest first
   USAGE: Loading home screen listings
   PERFORMANCE: O(n), indexed by postedTimestamp

   @Query("SELECT * FROM books WHERE id = :id LIMIT 1")
   suspend fun getBookById(id: String): BookEntity?
   PURPOSE: Get specific book by ID
   USAGE: Loading book detail screen
   PERFORMANCE: O(1), indexed by primary key

   @Query("SELECT * FROM books WHERE isFavorite = 1")
   suspend fun getFavoriteBooks(): List<BookEntity>
   PURPOSE: Get all favorite books
   USAGE: Favorites screen
   PERFORMANCE: O(k) where k = number of favorites

   @Query("SELECT * FROM books WHERE ownerId = :ownerId")
   suspend fun getBooksByOwner(ownerId: String): List<BookEntity>
   PURPOSE: Get books owned by specific user
   USAGE: My listings screen, seller profile
   PERFORMANCE: O(m) where m = user's books

   @Insert(onConflict = OnConflictStrategy.REPLACE)
   suspend fun insertBooks(books: List<BookEntity>)
   PURPOSE: Insert/update multiple books
   USAGE: Cache API response
   CONFLICT STRATEGY: REPLACE - overwrites existing entries
   PERFORMANCE: Batched insert, efficient

   @Insert(onConflict = OnConflictStrategy.REPLACE)
   suspend fun insertBook(book: BookEntity)
   PURPOSE: Insert/update single book
   USAGE: After creating/editing book
   CONFLICT STRATEGY: REPLACE - overwrites if exists
   PERFORMANCE: Single insert

   @Query("DELETE FROM books WHERE id = :id")
   suspend fun deleteBook(id: String)
   PURPOSE: Delete book from local cache
   USAGE: After deletion from API
   PERFORMANCE: O(1), indexed by primary key

   @Query("DELETE FROM books")
   suspend fun clearAllBooks()
   PURPOSE: Clear entire books table
   USAGE: Logout, database reset
   PERFORMANCE: O(n), truncates table

5.5 HOW ROOM IS USED IN THE APPLICATION
================================================================================

FLOW 1: Loading Books (Cache-First Strategy)
   
   User opens Home Screen
        │
        ├─→ [SYNC] Load from Room (immediate)
        │   └─→ Display cached books instantly
        │
        └─→ [ASYNC] Fetch from API (background)
            └─→ Retrofit calls backend
                ├─→ Get new books
                ├─→ Insert into Room
                └─→ Update UI with fresh data


FLOW 2: Creating a Book Listing
   
   User fills form and taps "Save"
        │
        ├─→ [SYNC] Insert into Room (optimistic update)
        │   └─→ Show in UI immediately (optimistic)
        │
        └─→ [ASYNC] POST to API
            ├─→ Server validates and stores
            └─→ Receive ID and update Room record


FLOW 3: Adding to Favorites
   
   User taps "❤️ Favorite" on book
        │
        ├─→ [SYNC] Update isFavorite=1 in Room
        │   └─→ Update UI instantly
        │
        └─→ [ASYNC] POST to API favorites endpoint
            └─→ Server stores favorite relationship


FLOW 4: Offline Access
   
   User has no internet connection
        │
        ├─→ API calls fail (gracefully)
        │
        └─→ Room provides cached data
            └─→ User can still browse previously loaded books

6.1 RETROFIT SETUP & CONFIGURATION
================================================================================

RETROFIT CLIENT: RetrofitClient.kt
Location: app/src/main/java/com/dennis/bookora/api/RetrofitClient.kt

CODE STRUCTURE:

   object RetrofitClient {
       private const val BASE_URL = "https://bookora.onenetwork-system.com/v1/"
       
       val apiService: ApiService by lazy {
           val logging = HttpLoggingInterceptor().apply {
               level = HttpLoggingInterceptor.Level.BODY  // Log request/response
           }
           
           val client = OkHttpClient.Builder()
               .addInterceptor(logging)  // Add logging interceptor
               .build()
           
           val gson = GsonBuilder()
               .setLenient()  // Flexible JSON parsing
               .create()
           
           Retrofit.Builder()
               .baseUrl(BASE_URL)
               .client(client)
               .addConverterFactory(GsonConverterFactory.create(gson))
               .build()
               .create(ApiService::class.java)
       }
   }

CONFIGURATION DETAILS:

   BASE_URL: "https://bookora.onenetwork-system.com/v1/"
   - Production backend server URL
   - All API endpoints are relative to this URL
   - Version 1 (v1) of the API

   HTTP Logging:
   - Logs all request headers and response bodies
   - Useful for debugging API issues
   - Set to BODY level (verbose)

   OkHttpClient:
   - HTTP client handling actual network requests
   - Can be extended with interceptors for:
      • Authentication headers
      • Request/response transformation
      • Connection pooling
      • Certificate pinning

   GSON Converter:
   - Converts JSON responses to Kotlin data classes
   - Uses Leniency for flexible JSON parsing
   - Handles missing fields gracefully

   Lazy Initialization:
   - ApiService created only when first accessed
   - Singleton pattern ensures one instance


6.2 API ENDPOINTS & OPERATIONS
================================================================================

BASE URL: https://bookora.onenetwork-system.com/v1/

ENDPOINT 1: AUTHENTICATION (auth.php)
───────────────────────────────────────────────────────────────

   A. USER LOGIN
      Method: POST
      Endpoint: auth.php?action=login
      
      Request Body:
         {
             "email": "user@example.com",
             "password": "password123"
         }
      
      Response:
         {
             "status": "success",
             "data": {
                 "user_id": "123",
                 "username": "john_doe",
                 "email": "user@example.com",
                 "avatar": "https://...",
                 "token": "jwt_token_here"
             }
         }
      
      FUNCTION: login()
         suspend fun login(
             @Query("action") action: String = "login",
             @Body body: Map<String, String>
         ): Response<ApiEnvelope<UserApiResponse>>
      
      HOW IT'S USED:
         1. User enters email and password
         2. Repository calls: apiService.login(body = {"email": "...", "password": "..."})
         3. Retrofit sends POST request to backend
         4. Backend validates credentials against MySQL users table
         5. If valid: returns JWT token
         6. Token stored locally in SharedPreferences
         7. User navigated to Dashboard


   B. USER REGISTRATION
      Method: POST
      Endpoint: auth.php?action=register
      
      Request Body:
         {
             "username": "john_doe",
             "email": "user@example.com",
             "password": "password123"
         }
      
      Response:
         {
             "status": "success",
             "data": {
                 "user_id": "123",
                 "token": "jwt_token_here",
                 ...
             }
         }
      
      FUNCTION: register()
         suspend fun register(
             @Query("action") action: String = "register",
             @Body body: Map<String, String>
         ): Response<ApiEnvelope<UserApiResponse>>
      
      HOW IT'S USED:
         1. New user fills registration form
         2. Repository validates input (email format, password strength)
         3. Calls: apiService.register(body = user data)
         4. Backend: Checks if email exists, hashes password, creates user
         5. Returns JWT token on success
         6. User auto-logged in with token


   C. GOOGLE SIGN-IN
      Method: POST
      Endpoint: auth.php?action=google_login
      
      Request Body:
         {
             "google_id_token": "id_token_from_google"
         }
      
      Response:
         {
             "status": "success",
             "data": {
                 "user_id": "123",
                 "token": "jwt_token_here",
                 ...
             }
         }
      
      FUNCTION: loginWithGoogle()
         suspend fun loginWithGoogle(
             @Query("action") action: String = "google_login",
             @Body body: Map<String, String>
         ): Response<ApiEnvelope<UserApiResponse>>
      
      HOW IT'S USED:
         1. User taps "Sign in with Google"
         2. Google Sign-In library opens Google auth dialog
         3. User authenticates with Google account
         4. Google returns ID token to app
         5. App sends token to backend: apiService.loginWithGoogle()
         6. Backend verifies token with Google, creates/updates user
         7. App receives JWT token for Bookora
         8. User logged in without email/password

7.2 MYSQL DATABASE SCHEMA
================================================================================

DATABASE: bookora

CORE TABLES:

TABLE 1: users
──────────────────────────────────────────────

CREATE TABLE users (
    user_id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(255) UNIQUE NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    phone VARCHAR(20),
    bio TEXT,
    avatar_url VARCHAR(500),
    rating DECIMAL(3,2) DEFAULT 0.0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    google_id VARCHAR(255) UNIQUE,
    is_active BOOLEAN DEFAULT TRUE
);

COLUMNS:
   - user_id: Unique identifier (auto-increment)
   - username: Display name
   - email: Login email (unique)
   - password_hash: BCrypt hashed password
   - phone: Contact phone number
   - bio: User biography
   - avatar_url: Profile picture URL
   - rating: Average rating (0-5 stars)
   - google_id: Google OAuth ID (for Google Sign-In)

INDEXES:
   - PRIMARY KEY: user_id
   - UNIQUE: email, username, google_id
   - INDEX: is_active (for active user queries)


TABLE 2: books
──────────────────────────────────────────────

CREATE TABLE books (
    book_id INT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(255) NOT NULL,
    author VARCHAR(255) NOT NULL,
    category VARCHAR(100),
    condition ENUM('NEW', 'GOOD', 'FAIR', 'POOR'),
    location VARCHAR(255),
    posted_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    cover_url VARCHAR(500),
    listing_type ENUM('GIVEAWAY', 'EXCHANGE', 'SELL'),
    description TEXT,
    owner_id INT NOT NULL,
    rating DECIMAL(3,2) DEFAULT 0.0,
    view_count INT DEFAULT 0,
    is_available BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (owner_id) REFERENCES users(user_id) ON DELETE CASCADE
);

COLUMNS:
   - book_id: Unique book identifier
   - title: Book title
   - author: Author name
   - category: Book category (Fiction, Science, etc.)
   - condition: Book physical condition
   - location: Book location
   - listing_type: Type of listing (giveaway, exchange, sell)
   - owner_id: User who posted the book (FK to users)
   - is_available: Whether book is still available

RELATIONSHIP:
   - Many books belong to ONE user
   - Foreign key: owner_id → users.user_id
   - ON DELETE CASCADE: If user deleted, their books deleted


TABLE 3: categories
──────────────────────────────────────────────

CREATE TABLE categories (
    category_id INT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(100) UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

COLUMNS:
   - category_id: Unique category ID
   - title: Category name (Fiction, Non-Fiction, Science, etc.)

PREDEFINED CATEGORIES:
   - Fiction
   - Non-Fiction
   - Science
   - History
   - Biography
   - Children's
   - Education
   - Technology
   - Philosophy
   - Poetry


TABLE 4: favorites
──────────────────────────────────────────────

CREATE TABLE favorites (
    favorite_id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,
    book_id INT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE CASCADE,
    FOREIGN KEY (book_id) REFERENCES books(book_id) ON DELETE CASCADE,
    UNIQUE KEY (user_id, book_id)
);

COLUMNS:
   - favorite_id: Unique favorite ID
   - user_id: User who favorited the book
   - book_id: Book that was favorited
   - created_at: When it was favorited

RELATIONSHIP:
   - Many-to-Many: Users can favorite many books, books can be favorited by many users
   - Prevents duplicates with UNIQUE constraint


TABLE 5: conversations
──────────────────────────────────────────────

CREATE TABLE conversations (
    conversation_id INT PRIMARY KEY AUTO_INCREMENT,
    user_id_1 INT NOT NULL,
    user_id_2 INT NOT NULL,
    book_id INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id_1) REFERENCES users(user_id),
    FOREIGN KEY (user_id_2) REFERENCES users(user_id),
    FOREIGN KEY (book_id) REFERENCES books(book_id)
);

COLUMNS:
   - conversation_id: Unique conversation ID
   - user_id_1, user_id_2: Two participants
   - book_id: Book being discussed (nullable, for general chat)

PURPOSE:
   - Stores chat conversation metadata
   - Links two users together
   - Associates optional book being discussed


TABLE 6: messages
──────────────────────────────────────────────

CREATE TABLE messages (
    message_id INT PRIMARY KEY AUTO_INCREMENT,
    conversation_id INT NOT NULL,
    sender_id INT NOT NULL,
    content TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    is_read BOOLEAN DEFAULT FALSE,
    FOREIGN KEY (conversation_id) REFERENCES conversations(conversation_id) ON DELETE CASCADE,
    FOREIGN KEY (sender_id) REFERENCES users(user_id) ON DELETE CASCADE
);

COLUMNS:
   - message_id: Unique message ID
   - conversation_id: Which conversation this is part of
   - sender_id: Who sent the message
   - content: Message text
   - is_read: Whether recipient has read it

RELATIONSHIP:
   - Many messages belong to ONE conversation
   - Messages deleted when conversation deleted


TABLE 7: notifications
──────────────────────────────────────────────

CREATE TABLE notifications (
    notification_id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,
    type VARCHAR(50), -- 'message', 'favorite', 'new_listing'
    title VARCHAR(255),
    content TEXT,
    related_id INT, -- ID of related object (book_id, user_id, etc.)
    is_read BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE CASCADE
);

COLUMNS:
   - notification_id: Unique notification ID
   - user_id: Who receives this notification
   - type: Type of notification
   - is_read: Whether user has seen it


7.3 DATA FLOW: CLIENT TO SERVER TO DATABASE
================================================================================

EXAMPLE: Creating a Book Listing

STEP 1: USER CREATES IN APP
   User fills form in CreateBookScreen:
   - Title: "The Great Gatsby"
   - Author: "F. Scott Fitzgerald"
   - Category: "Fiction"
   - Condition: "GOOD"
   - Listing Type: "EXCHANGE"
   - Description: "..."
   - Cover Image: (selected/captured)

STEP 2: APP PREPARES DATA
   Kotlin Code:
   val bookData = mapOf(
       "action" to "create",
       "user_id" to "123",
       "title" to "The Great Gatsby",
       "author" to "F. Scott Fitzgerald",
       "category" to "Fiction",
       "condition" to "GOOD",
       "listing_type" to "EXCHANGE",
       "location" to "Nairobi, Kenya",
       "description" to "Lightly used...",
       "cover_image" to base64EncodedImage
   )

STEP 3: RETROFIT SENDS HTTP REQUEST
   POST https://bookora.onenetwork-system.com/v1/books.php HTTP/1.1
   Content-Type: application/json
   
   {
       "action": "create",
       "user_id": "123",
       "title": "The Great Gatsby",
       "author": "F. Scott Fitzgerald",
       "category": "Fiction",
       "condition": "GOOD",
       "listing_type": "EXCHANGE",
       "location": "Nairobi, Kenya",
       "description": "Lightly used...",
       "cover_image": "iVBORw0KGgoAAAANS..."
   }

STEP 4: PHP BACKEND PROCESSES (books.php)
   
   PHP Code receives request:
   ```php
   $data = json_decode(file_get_contents("php://input"), true);
   
   if ($data['action'] == 'create') {
       // Validate input
       if (empty($data['title']) || empty($data['author'])) {
           return error("Title and author required");
       }
       
       // Decode image
       $imageData = base64_decode($data['cover_image']);
       $imagePath = 'uploads/books/' . uniqid() . '.jpg';
       file_put_contents($imagePath, $imageData);
       
       // Prepare INSERT query
       $query = "INSERT INTO books 
                 (title, author, category, condition, listing_type, 
                  location, description, owner_id, cover_url, created_at) 
                 VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, NOW())";
       
       $stmt = $db->prepare($query);
       $stmt->bind_param(
           "ssssssssi",
           $data['title'],
           $data['author'],
           $data['category'],
           $data['condition'],
           $data['listing_type'],
           $data['location'],
           $data['description'],
           $data['user_id'],
           $imagePath
       );
       
       if ($stmt->execute()) {
           $book_id = $db->insert_id;
           return success([
               "book_id" => $book_id,
               "title" => $data['title'],
               ...
           ]);
       }
   }
   ```

STEP 5: MYSQL INSERTS RECORD
   SQL Executed:
   INSERT INTO books 
   (title, author, category, condition, listing_type, 
    location, description, owner_id, cover_url, created_at) 
   VALUES 
   ('The Great Gatsby', 'F. Scott Fitzgerald', 'Fiction', 'GOOD', 
    'EXCHANGE', 'Nairobi, Kenya', 'Lightly used...', 123, 
    'uploads/books/5f8e3d2c.jpg', '2024-01-15 10:30:00');
   
   New book_id: 1001 (auto-increment)

STEP 6: DATABASE RESPONSE
   MySQL returns success and new book_id

STEP 7: PHP RETURNS JSON RESPONSE
   HTTP/1.1 200 OK
   Content-Type: application/json
   
   {
       "status": "success",
       "data": {
           "id": "1001",
           "title": "The Great Gatsby",
           "author": "F. Scott Fitzgerald",
           "category": "Fiction",
           "condition": "GOOD",
           "listing_type": "EXCHANGE",
           "location": "Nairobi, Kenya",
           "description": "Lightly used...",
           "owner_id": "123",
           "cover_url": "https://bookora.onenetwork-system.com/uploads/books/5f8e3d2c.jpg",
           "posted_date": "2024-01-15",
           "rating": 0.0
       }
   }

STEP 8: RETROFIT PARSES RESPONSE
   Retrofit's GSON converter parses JSON into BookApiResponse object

STEP 9: REPOSITORY PROCESSES RESPONSE

8.6 ROOM CRUD OPERATIONS
================================================================================

CREATE: Insert new book
   Room Query: INSERT INTO books VALUES (...)
   API Integration: POST books.php
   Result: New book available in app and server

READ: Display books
   Room Query: SELECT * FROM books ORDER BY postedTimestamp DESC
   API Integration: GET books.php?action=list
   Result: Books displayed in UI (cached first, then refreshed)

UPDATE: Edit book listing
   Room Query: UPDATE books SET title=?, description=? WHERE id=?
   API Integration: PUT books.php?id=book_id
   Result: Changes reflected in UI and server

DELETE: Remove book
   Room Query: DELETE FROM books WHERE id=?
   API Integration: DELETE books.php?id=book_id
   Result: Book removed from app and server
